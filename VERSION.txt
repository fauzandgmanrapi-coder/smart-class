SMART CLASS ONLINE v2026-10-28-v9.0.4
====================================

Perbaikan MIKRO dari v2026-10-28-v9.0.3: keandalan route
/api/asisten (timeout & kecepatan model), menggantikan
paket v9.0.3. TIDAK ada migrasi SQL baru — folder
supabase/ identik dengan v9/v8.

Diagnosis (terverifikasi dari live): dengan rantai 3.x
v9.0.3 asisten SEMPAT menjawab benar (HTTP 200), tetapi
panggilan berikutnya gagal 502 {upstream_status:0,
upstream_code:"FETCH_FAILED"} — termasuk probe satu
giliran. Artinya: model pertama (gemini-3.8-flash, free
tier) kadang merespons LEBIH LAMBAT dari timeout
per-percobaan 20 detik sehingga fetch dibatalkan, dan
desain v9.0.3 TIDAK jatuh ke model berikutnya saat fetch
gagal/timeout. Ini BUKAN bug riwayat percakapan.

Yang berubah di v9.0.4 (HANYA src/app/api/asisten/route.ts):
- Ditambahkan export maxDuration = 60 agar fungsi boleh
  memuat beberapa percobaan berurutan.
- DAFTAR_MODEL baru — model LITE di depan (lebih cepat,
  kuota lebih ringan; kualitas cukup untuk tanya-jawab
  panduan), model penuh tetap cadangan di belakang:
  "gemini-3.1-flash-lite" -> "gemini-3.5-flash-lite" ->
  "gemini-3.8-flash" -> "gemini-3.6-flash".
- generationConfig kini memuat thinkingConfig
  { thinkingBudget: 0 } — mematikan penalaran berlebih
  model Flash agar jawaban panduan cepat keluar.
  Pengaman kompatibilitas: bila suatu percobaan dibalas
  400 dan pesan error Google mengandung kata "thinking",
  model yang sama dicoba ulang sekali TANPA
  thinkingConfig, dan field itu tidak dipakai lagi selama
  sisa request tersebut. Hasil percobaan ulang mengikuti
  aturan normal (OK -> {reply}; 404 -> model berikutnya;
  error lain -> 502 diagnostik).
- Timeout/fetch gagal kini JATUH ke model berikutnya
  (dulu langsung FETCH_FAILED): kegagalan terakhir
  dicatat — jenis fetch/timeout atau 404 beserta
  status/kode — lalu rantai lanjut. Anggaran total:
  percobaan baru tidak dimulai bila waktu sejak awal
  request sudah > 45 detik; rantai berhenti dan membalas
  502 dengan diagnostik kegagalan TERAKHIR (FETCH_FAILED
  bila terakhir fetch/timeout; 404 NOT_FOUND bila
  terakhir 404).
- Aturan lain TETAP: respons OK -> {reply}; error non-404
  (selain kasus thinking di atas) -> langsung 502
  diagnostik pola v9.0.1 (upstream_status +
  upstream_code), tanpa jatuh ke model lain; payload
  tidak valid -> 400; kunci belum dipasang -> 503
  {error:"not_configured"}; timeout per percobaan tetap
  20 detik; kunci API tidak pernah masuk log/respons;
  log ringkas per kegagalan tetap menyertakan nama
  model. UI AsistenChat.tsx tidak berubah.
- package.json -> versi 1.6.4.
