SMART CLASS ONLINE v2026-10-28-v9.0.3
====================================

Perbaikan MIKRO dari v2026-10-28-v9.0.2: rantai model
route /api/asisten diganti dari keluarga Gemini 2.x ke
keluarga Gemini 3.x. Sebab pastinya (riset web Okt 2026,
multi-sumber): Google membatasi model Gemini 2.5/2.0
hanya untuk developer yang pernah memakainya — API
key/proyek BARU menerima 404 "no longer available to
new users" untuk gemini-2.5-flash dan
gemini-2.5-flash-lite, sedangkan gemini-2.0-flash sudah
hilang untuk semua orang. Itulah mengapa SELURUH rantai
v9.0.2 tetap 404 di live user padahal key-nya valid.
Pengganti resmi yang ditunjuk error Google untuk
2.5-flash adalah gemini-3.8-flash; model free-tier saat
ini: 3.8 Flash, 3.6 Flash, 3.5 Flash-Lite, 3.1 Flash-Lite.
Paket ini MENGGANTIKAN paket v9.0.2. TIDAK ada migrasi
SQL baru — folder supabase/ identik dengan v9/v8.

Yang berubah di v9.0.3 (HANYA src/app/api/asisten/route.ts):
- Isi konstanta DAFTAR_MODEL menjadi:
  "gemini-3.8-flash" -> "gemini-3.6-flash" ->
  "gemini-3.5-flash-lite" -> "gemini-3.1-flash-lite".
  Urutan ini penting: yang terkuat dan pasti tersedia
  untuk user baru ditaruh paling depan.
- SEMUA logika lain identik dengan v9.0.2: isi
  permintaan sama untuk tiap model (systemInstruction,
  contents, generationConfig), kunci dari env server
  GEMINI_API_KEY, timeout 20 detik per percobaan.
- Respons OK dari model mana pun -> langsung balas
  {reply}.
- Respons 404 -> dicatat "asisten-upstream" + nama model
  + status + kode Google (pola v9.0.1), lalu LANJUT ke
  model berikutnya.
- Respons error SELAIN 404 (400 key tidak valid, 403,
  429 kuota, dst) -> TIDAK lanjut ke model lain;
  langsung balas 502 diagnostik pola v9.0.1
  (upstream_status + upstream_code) untuk error itu.
- fetch gagal (jaringan/timeout) -> langsung 502
  {error:"upstream", upstream_status:0,
  upstream_code:"FETCH_FAILED"} seperti v9.0.1.
- Bila SEMUA model menjawab 404 -> balas 502 dengan
  upstream_status/upstream_code dari respons TERAKHIR
  (404 NOT_FOUND), sama seperti diagnosis v9.0.1.
- Kunci API TIDAK pernah ditulis ke log maupun respons.
- Perilaku lain identik: payload tidak valid -> 400,
  kunci belum dipasang -> 503 {error:"not_configured"}.
  UI AsistenChat.tsx tidak berubah.
- package.json -> versi 1.6.3.

Seluruh isi v9.0.2 & v9 tetap berlaku (rantai model
cadangan + diagnostik asisten, tombol chat melayang
setelah login, basis pengetahuan asisten-pengetahuan.ts
dari Manual Book v5 + fitur v8) dan seluruh isi v8.2.1

Urutan deploy (dari v9.0.2 — TANPA langkah migrasi SQL):
1) Ekstrak paket ke folder BARU, upload seluruh isinya ke
   GitHub (timpa file lama).
2) Env GEMINI_API_KEY di Vercel TIDAK perlu diubah —
   pastikan tetap terpasang (semua environment, TANPA
   NEXT_PUBLIC_). Kunci bersifat rahasia — jangan
   dibagikan, jangan masuk GitHub/chat.
3) Redeploy, tunggu selesai, lalu Ctrl+F5 di aplikasi.
4) Login -> klik tombol chat -> ajukan pertanyaan;
   asisten kini memakai model 3.x pertama yang tersedia.
Panduan deploy lengkap v9 ada di folder smart-class-v9
(panduan-deploy-v9.md).
